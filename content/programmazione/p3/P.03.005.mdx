<Scene title="Variabili locali">
Una variabile creata **dentro** una funzione è **locale**: esiste solo mentre la funzione è in esecuzione, e solo lì dentro.

```python
def calcola():
    totale = 10

calcola()
print(totale)
```

<Log lines={[
  "NameError: name 'totale' is not defined",
]} caption="Fuori dalla funzione, totale non esiste." />

Anche i **parametri** sono variabili locali. Quando la funzione finisce, tutte le sue variabili locali spariscono.

Il vantaggio è che funzioni diverse possono usare gli stessi nomi (`totale`, `n`, `i`) senza disturbarsi a vicenda.

<Scene title="Variabili globali">
Una variabile creata **fuori** da ogni funzione è **globale**. Una funzione può **leggerla**:

```python
squadra = "Aquile"

def presenta():
    print("Gioca la squadra", squadra)

presenta()
```

<Log lines={[
  "Gioca la squadra Aquile",
]} caption="Leggere una variabile globale è permesso." />

Ma se dentro la funzione **assegni** un valore a quel nome, Python crea una nuova variabile **locale**, anche se ne esiste una globale con lo stesso nome. Nel caso di Elena, `punti = punti + 1` cerca di leggere la `punti` locale prima che esista: da qui l'errore (`UnboundLocalError`).

<Callout kind="attenzione">
Dentro una funzione, **assegnare** a un nome lo rende locale per tutta la funzione. Leggere un nome senza assegnarlo lo cerca anche fuori.
</Callout>

<Say who="sensei">Leggere sì, assegnare no. Questa è la regola di partenza.</Say>
</Scene>

<Scene title="Come si risolve">
Python ha la parola `global`, che dice «voglio modificare la variabile globale». Funziona:

```python
punti = 0

def aggiungi_punto():
    global punti
    punti = punti + 1

aggiungi_punto()
print(punti)
```

<Log lines={[
  "1",
]} caption="Con global la funzione modifica la variabile esterna." />

Funziona, ma di solito **non è la soluzione migliore**: una funzione che cambia variabili esterne è difficile da capire e da provare, perché il suo effetto dipende da qualcosa che non vedi nella chiamata. Meglio far entrare i dati con un parametro e farli uscire con `return`:

```python
def aggiungi_punto(punti):
    return punti + 1

punti = 0
punti = aggiungi_punto(punti)
print(punti)
```

<Callout kind="regola">
Preferisci **parametri e return** a `global`. La funzione diventa autonoma: tutto quello che usa lo vedi nelle parentesi, tutto quello che produce lo vedi nel return.
</Callout>

<Say who="assistente">Chiamata dopo chiamata, il punteggio cresce: `punti = aggiungi_punto(punti)` è chiaro anche a chi legge per la prima volta.</Say>
</Scene>

<Scene title="Rapporto finale">
<Recap xp={20}>
- Una variabile creata dentro una funzione è locale e sparisce quando la funzione finisce.
- Una variabile creata fuori da ogni funzione è globale e si può leggere ovunque.
- Assegnare a un nome dentro una funzione crea una variabile locale, non modifica la globale.
- `global` permette di modificarla, ma è meglio passare i dati con parametri e return.
- Caso chiuso: Elena scrive `punti = aggiungi_punto(punti)` e il punteggio sale senza errori.
</Recap>
