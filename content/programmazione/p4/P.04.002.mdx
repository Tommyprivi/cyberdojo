<Scene title="Il muro di testo">
Elena fa partire il programma dei voti del corso di teatro e sullo schermo compaiono sette righe di testo rosso. Si spaventa: «Si è rotto tutto!».

Non si è rotto niente. Quel testo si chiama **traceback** («traccia a ritroso») ed è il modo con cui Python ti dice **dove** e **perché** si è fermato. È un aiuto, non un'accusa.

La domanda del caso: **da dove si comincia a leggere un traceback?**

<Say who="sensei">Un traceback è un biglietto lasciato da Python. Si legge dal fondo, perché il fondo è la risposta.</Say>
</Scene>

{/* screen */}

<Scene title="Il programma">
Ecco il programma di Elena. Calcola la media dei voti.

```python
def media(voti):
    return sum(voti) / len(voti)

def rapporto(voti):
    return "Media: " + str(media(voti))

print(rapporto([]))
```

Le righe sono numerate da 1: la riga 2 è il `return` di `media`, la riga 5 è quello di `rapporto`, la riga 7 è il `print` finale. La lista dei voti è vuota, e dividere per `len([])`, cioè 0, non si può.

<Say who="assistente">Prova a seguire il percorso a mente: il print chiama rapporto, rapporto chiama media, media divide per zero.</Say>
</Scene>

{/* screen */}

<Scene title="Il traceback">
<Log lines={[
  "Traceback (most recent call last):",
  "  File \"voti.py\", line 7, in <module>",
  "    print(rapporto([]))",
  "  File \"voti.py\", line 5, in rapporto",
  "    return \"Media: \" + str(media(voti))",
  "  File \"voti.py\", line 2, in media",
  "    return sum(voti) / len(voti)",
  "ZeroDivisionError: division by zero",
]} caption="Il traceback del programma dei voti (nelle versioni recenti possono comparire anche dei segni ^^^ sotto la riga)." />

Come si legge:
- **L'ultima riga** dice il **tipo** (`ZeroDivisionError`) e il **messaggio** (`division by zero`, «divisione per zero»). È la prima cosa da leggere.
- Poco sopra c'è la riga di codice dove il problema è avvenuto: `return sum(voti) / len(voti)`, alla riga 2 di `voti.py`.
- Le coppie `File ... line ...` più in alto sono la **catena delle chiamate**: chi ha chiamato chi.

<Callout kind="regola">
Si legge **dal basso**: prima il tipo e il messaggio, poi la riga del problema, e solo se serve si risale la catena per capire come ci si è arrivati.
</Callout>

<Say who="sensei">La frase «most recent call last» significa che l'ultima chiamata sta in fondo. Ecco perché si parte da lì.</Say>
</Scene>

{/* screen */}

<Scene title="La catena delle chiamate">
Il traceback elenca le funzioni dalla prima all'ultima chiamata.

<Flow
  caption="Il percorso del programma, dall'alto in basso nel traceback."
  steps={[
    { icon: "code", title: "Programma principale", text: "riga 7: print(rapporto([]))" },
    { icon: "gear", title: "rapporto", text: "riga 5: chiama media(voti)" },
    { icon: "bug", title: "media", text: "riga 2: divide per zero e si ferma" },
  ]}
/>

La riga dove Python si ferma è l'ultima, ma la **causa** può stare più su: qui il vero guaio è che il programma principale ha passato una lista vuota. Dividere per zero è solo il punto dove la cosa è diventata impossibile.

<Callout kind="trucco">
Alcuni errori comuni e il loro significato: `NameError` (un nome che non esiste, spesso per un errore di battitura), `TypeError` (tipi che non vanno insieme, come testo più numero), `IndexError` (posizione fuori da una lista), `KeyError` (chiave assente in un dizionario).
</Callout>

<Say who="assistente">Il messaggio ti dice cosa non è andato. La catena ti dice come ci sei arrivato. Servono tutti e due.</Say>
</Scene>

<Scene title="Rapporto finale">
<Recap xp={20}>
- Il traceback è il messaggio con cui Python spiega dove e perché si è fermato.
- Si legge dal basso: l'ultima riga ha il tipo e il messaggio dell'errore.
- Le righe sopra danno il file, il numero di riga e la catena di chiamate tra le funzioni.
- Caso chiuso: nel programma dei voti, ZeroDivisionError in media era causato da una lista vuota passata dall'inizio.
</Recap>
