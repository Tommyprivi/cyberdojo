<Scene title="Il totale che non torna">
Elena ha scritto una funzione che somma i prezzi dei biglietti per le prove del gruppo di teatro. Non c'è nessun errore rosso, ma il risultato è sbagliato.

```python
def totale(prezzi):
    somma = 0
    for p in prezzi:
        somma = p
    return somma

print(totale([5, 10, 3]))
```

Dovrebbe stampare 18. Stampa 3. Nessun messaggio ti dice dove guardare: è un errore di logica.

La domanda del caso: **come si scopre che cosa succede dentro un programma mentre gira?**

<Scene title="Il debug con le stampe">
Il modo più semplice per osservare è `print`: aggiungi righe che mostrano i valori.

```python
def totale(prezzi):
    somma = 0
    for p in prezzi:
        somma = p
        print("p =", p, "somma =", somma)
    return somma

print(totale([5, 10, 3]))
```

<Log lines={[
  "p = 5 somma = 5",
  "p = 10 somma = 10",
  "p = 3 somma = 3",
  "3",
]} caption="Dopo il secondo giro la somma dovrebbe essere 15, non 10." />

Ecco l'indizio: la somma non cresce, viene **sostituita** a ogni giro. La riga giusta è `somma += p` (cioè `somma = somma + p`), che aggiunge invece di sostituire.

<Callout kind="attenzione">
Le stampe di debug vanno **tolte** a lavoro finito. Un programma che stampa righe che nessuno ha chiesto confonde chi lo usa.
</Callout>

<Say who="sensei">Una print ben messa vale mille supposizioni. Ma poi toglila.</Say>
</Scene>

<Scene title="Il debugger">
Il **debugger** è uno strumento che ferma il programma e ti lascia guardare e avanzare con calma. In Python c'è già, si chiama **pdb**. Per usarlo basta scrivere `breakpoint()` dove vuoi fermarti.

```python
def totale(prezzi):
    somma = 0
    for p in prezzi:
        somma = p
        breakpoint()
    return somma
```

Il programma si ferma e compare il prompt `(Pdb)`. Ecco i comandi principali:

- `n` (*next*): esegui la riga corrente e passa alla successiva.
- `s` (*step*): se la riga chiama una funzione, entra dentro la funzione.
- `p nome`: stampa il valore di una variabile, per esempio `p somma`.
- `c` (*continue*): riparti finché non incontri un altro `breakpoint()`, o fino alla fine.
- `q` (*quit*): esci dal debugger e dal programma.

<Log lines={[
  "(Pdb) p p",
  "5",
  "(Pdb) p somma",
  "5",
  "(Pdb) c",
]} caption="Una sessione di esempio: controlli i valori e riparti." />

<Callout kind="curiosita">
Anche gli editor come Visual Studio Code e IDLE hanno un debugger a pulsanti: puoi mettere un «punto di arresto» cliccando accanto al numero di riga. Funziona allo stesso modo, ma senza scrivere i comandi.
</Callout>

<Say who="assistente">Il debugger è più lento da usare di una print la prima volta. Ma quando i valori sono tanti, ti fa risparmiare un sacco di tempo.</Say>
</Scene>
