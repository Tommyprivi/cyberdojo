<Scene title="DNS: dove vuole andare">
Prima di collegarsi a un sito, il computer chiede al **DNS** l'indirizzo IP del nome. Quasi sempre su UDP, porta **53**, **senza cifratura**.

<Log
  lines={[
    "11  10:14:03.201  192.168.1.20 -> 192.168.1.1   DNS  Richiesta  A  www.esempio-meteo.it",
    "12  10:14:03.215  192.168.1.1  -> 192.168.1.20  DNS  Risposta   A  203.0.113.40  (TTL 300)",
    "13  10:14:09.700  192.168.1.20 -> 192.168.1.1   DNS  Richiesta  A  aggiorna.nonesiste-xyz.example",
    "14  10:14:09.731  192.168.1.1  -> 192.168.1.20  DNS  Risposta   Nome inesistente (NXDOMAIN)",
  ]}
  caption="Filtro: dns   ·   campi utili: dns.qry.name, dns.flags.rcode"
/>

Il DNS ti dice **che cosa il computer voleva raggiungere**, anche se poi la connessione è cifrata. Una riga **NXDOMAIN** (rcode 3) vuol dire «questo nome non esiste»: una o due sono normali (errori di battitura), **molte di seguito** meritano attenzione.

<Callout kind="curiosita">
Il DNS «cifrato» (DNS su HTTPS o su TLS) esiste e protegge la privacy. Ma in azienda può togliere visibilità ai controlli: per questo se ne parla spesso nelle policy di rete.
</Callout>

<Say who="assistente">Il DNS è la rubrica che il computer sfoglia ad alta voce, davanti a tutti. Ascoltala.</Say>
</Scene>

<Scene title="HTTP: tutto in chiaro">
Sulla porta **80**, HTTP viaggia **in chiaro**: richiesta e risposta si leggono come testo.

<Log
  lines={[
    "21  10:14:04.010  192.168.1.20 -> 192.168.1.50  HTTP  GET /intranet/listino.html",
    "22  10:14:04.032  192.168.1.50  -> 192.168.1.20  HTTP  HTTP/1.1 200 OK (text/html)",
    "23  10:14:11.440  192.168.1.20 -> 192.168.1.50  HTTP  GET /intranet/admin.html",
    "24  10:14:11.452  192.168.1.50  -> 192.168.1.20  HTTP  HTTP/1.1 403 Forbidden",
  ]}
  caption="Filtro: http   ·   campi utili: http.request.method, http.response.code, http.host"
/>

Che cosa leggi: un GET riuscito (**200**) e un secondo GET respinto (**403**, «vietato»). Il **403** è una risposta del server: la rete ha funzionato benissimo, è il server che ha detto «tu qui non entri».

Nel flusso HTTP trovi anche l'intestazione **User-Agent**, che dichiara il programma usato: un `python-requests` dove ti aspetti un browser è un indizio.

<Callout kind="attenzione">
Se compare una password o un cookie di sessione in chiaro, **è un problema da segnalare**: quella pagina deve passare a HTTPS.
</Callout>

<Say who="sensei">In HTTP vedi tutto: percorso, risposte, intestazioni. Per questo oggi si usa solo per cose che non contano.</Say>
</Scene>

<Scene title="TLS: la busta chiusa">
Con **HTTPS** (porta **443**) prima si apre la connessione TCP, poi parte la stretta di mano **TLS**: il computer manda un **Client Hello** («ciao, parliamo in modo cifrato, ecco le mie opzioni»), il server risponde con **Server Hello** e il suo certificato, poi i dati viaggiano cifrati.

<Log
  lines={[
    "31  10:14:03.300  192.168.1.20 -> 203.0.113.40  TLSv1.3  Client Hello  (SNI: www.esempio-meteo.it)",
    "32  10:14:03.322  203.0.113.40  -> 192.168.1.20  TLSv1.3  Server Hello, Change Cipher Spec",
    "33  10:14:03.325  203.0.113.40  -> 192.168.1.20  TLSv1.3  Dati applicativi (cifrati)",
    "34  10:14:03.330  192.168.1.20 -> 203.0.113.40  TLSv1.3  Dati applicativi (cifrati)",
  ]}
  caption="Filtro: tls   ·   Client Hello: tls.handshake.type == 1"
/>

Che cosa **resta visibile**: gli indirizzi IP, le porte, gli orari, **quanti dati** passano, la versione di TLS e di solito il **nome del sito** nel campo **SNI** del Client Hello. Che cosa **non si vede**: pagine, parole chiave, password, contenuto.

<Scene title="Rapporto finale">
<Recap xp={20}>
- DNS (UDP 53, in chiaro) dice dove il computer vuole andare; molti NXDOMAIN di seguito meritano attenzione.
- HTTP (porta 80) si legge tutto; i codici 200, 403, 404 sono risposte del server, non guasti di rete. HTTPS (443) cifra il contenuto, ma restano visibili IP, orari, quantità e spesso il nome del sito (SNI).
- Nel rapporto si separano i fatti visti nella cattura dalle ipotesi.
</Recap>
