<Scene title="Ordine inviato due volte">
Il bot di Marta invia un ordine demo di 10 azioni. La rete è lenta, la risposta non arriva, il programma ripete l'invio. Risultato: nel conto demo ci sono **20 azioni** invece di 10.

Con soldi finti è una lezione. Con soldi veri sarebbe un errore costoso.

La domanda del caso: **come si costruisce e si invia un ordine in modo che gli errori si vedano subito e non si moltiplichino?**

<Scene title="L'ordine è un dizionario">
Un ordine è un insieme di campi. In Python è un dizionario:

```python
ordine = {
    "client_order_id": "bot-2026-10-21-0001",
    "symbol": "AAA",
    "side": "buy",
    "type": "limit",
    "qty": 10,
    "limit_price": 50.00,
    "time_in_force": "day",
}
```

- `symbol`: il simbolo dello strumento (qui un titolo inventato).
- `side`: `buy` compra, `sell` vende.
- `type`: `limit` vuol dire «non pagare più di questo prezzo».
- `time_in_force`: `day` vale fino a fine giornata.
- `client_order_id`: un codice **deciso da te**, unico per ogni ordine.

<Say who="assistente">Il client_order_id è come lo scontrino con il numero: se lo ripresenti, il broker capisce che è lo stesso ordine.</Say>
</Scene>

<Scene title="Prima si controlla">
Prima di inviare, il programma controlla l'ordine. Così un errore si ferma in casa. Provalo:

<PythonTerminal code={"def controlla_ordine(o):\n    if o['qty'] <= 0:\n        return 'quantità non valida'\n    if o['type'] == 'limit' and o.get('limit_price') is None:\n        return 'manca il prezzo limite'\n    return 'ok'\n\nprint(controlla_ordine({'qty': 10, 'type': 'limit', 'limit_price': 50.0}))\nprint(controlla_ordine({'qty': 0, 'type': 'market'}))\nprint(controlla_ordine({'qty': 5, 'type': 'limit'}))"} />

Risultato atteso: `ok`, poi `quantità non valida`, poi `manca il prezzo limite`.

<Callout kind="regola">
Un ordine passa da **tre porte**: controllo del formato, controllo dell'ambiente (demo), controllo dei limiti (quantità massima). Se una si chiude, non parte niente.
</Callout>

<Scene title="L'invio, solo in demo">
Con la libreria `requests` l'invio è breve. Nota: indirizzo demo, chiave letta dall'ambiente, timeout, controllo dell'ambiente.

```python
import os
import requests

BASE_URL = "https://api.example-broker.test/paper/v1"
if "/paper/" not in BASE_URL:
    raise SystemExit("Indirizzo non demo: mi fermo.")

chiave = os.environ["BROKER_PAPER_KEY"]
risposta = requests.post(
    f"{BASE_URL}/orders",
    json=ordine,
    headers={"Authorization": f"Bearer {chiave}"},
    timeout=10,
)
print(risposta.status_code)
```

Quello che non c'è: nessuna chiave scritta nel codice, nessun indirizzo reale, nessun invio senza timeout.

<Scene title="Rapporto finale">
<Recap xp={20}>
- Un ordine è un dizionario di campi (simbolo, lato, tipo, quantità, prezzo limite) con un client_order_id deciso da te.
- Si controlla prima: formato, ambiente demo, limiti. Se un controllo fallisce, non parte niente.
- L'invio usa chiave dall'ambiente, indirizzo demo e timeout. Mai un ordine «nuovo» a ogni tentativo.
</Recap>
