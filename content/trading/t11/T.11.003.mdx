<Scene title="Il target">
Il **target** è la cosa che il modello deve prevedere. Qui è semplice: **domani il rendimento è positivo (1) oppure no (0)**.

Convenzione: la riga del giorno t contiene le feature note a fine giornata t, e il target è il rendimento del giorno **t+1**. In pandas si usa `shift(-1)`, che «tira su» di una riga il valore del giorno dopo.

```python
import pandas as pd

r = pd.Series([1, -2, 3, -1, 2, 1])      # rendimenti in %
target = (r.shift(-1) > 0).astype(int)
print(target.tolist())
```

<Log lines={[
  "[0, 1, 0, 1, 1, 0]",
]} />

Controlliamo a mano. Riga 1: domani (−2) non è positivo, quindi **0**. Riga 2: domani vale 3, quindi **1**. Riga 3: domani vale −1, quindi **0**. E così via.

<Callout kind="attenzione">
L'ultimo **0** è una trappola. Dopo l'ultimo giorno non c'è un «domani»: il valore è NaN, e il confronto di NaN con 0 dà False, che diventa 0. Sembra un ribasso, ma è un **buco**. Quella riga va eliminata.
</Callout>

<Say who="assistente">Se un target viene da un confronto con NaN, il risultato è falso senza che pandas ti avvisi. Guarda sempre l'ultima riga.</Say>
</Scene>

<Scene title="La perdita di dati">
Si ha **perdita di dati** (in inglese *data leakage*) quando il modello riceve in ingresso informazioni che, nella realtà, **non avrebbe ancora**.

Il caso di Luca è il più brutale: la feature «rendimento_domani» **è** il target. Ovvio che il modello «indovina».

Ma i casi veri sono più sottili:

- una media mobile **centrata** (`rolling(3, center=True)`) include anche il giorno dopo;
- una **normalizzazione** con media e deviazione standard calcolate su **tutto** il periodo: il passato «conosce» le statistiche del futuro;
- un target su 5 giorni, con righe che si sovrappongono tra addestramento e test.

<Scene title="La normalizzazione giusta">
Molti modelli vogliono feature **normalizzate** (stessa scala). Il modo corretto: calcolare media e deviazione standard **solo sui dati di addestramento**, poi applicarle al test.

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler().fit(X_addestramento)     # impara solo dal passato
X_add = scaler.transform(X_addestramento)
X_test = scaler.transform(X_test)                  # applica, senza reimparare
```

Qui `X_addestramento` e `X_test` sono le tabelle di feature già divise per data: ne parla la prossima lezione.

<Callout kind="attenzione">
Sbagliato: `StandardScaler().fit(X_tutto)`. Sembra innocuo, ma il test ha già «insegnato» qualcosa all'addestramento.
</Callout>

<Say who="assistente">La regola è la stessa ovunque: quello che il test non può ancora sapere, non entra mai nel calcolo.</Say>
</Scene>
