<Scene title="Il report copiato a mano">
Ogni mese Giulia prepara un report delle vendite per il socio. Calcola i numeri in R, copia i grafici in un documento di testo, riscrive le cifre a mano. A marzo cambia i dati ma dimentica di aggiornare un numero nel titolo: il socio legge «Roma 120 euro» accanto a un grafico che ne mostra 150.

Il problema non è la distrazione. È che **il report e l'analisi sono due cose separate**, e tenerle allineate a mano è un lavoro che qualcuno prima o poi sbaglia.

La soluzione si chiama **report riproducibile**: un solo file che contiene testo, codice e risultati. Quando i dati cambiano, si preme un pulsante e tutto si rifà.

La domanda del caso: **come si fa un documento che si aggiorna da solo?**

<Say who="sensei">Se un numero in un report l'hai scritto tu a mano, un giorno sarà sbagliato. I numeri li scrive il codice.</Say>
</Scene>

<Scene title="Quarto e R Markdown">
Per scrivere un report che si rifà da solo ci sono due strumenti, molto simili:

- **R Markdown** (file `.Rmd`): il metodo classico, nato per R;
- **Quarto** (file `.qmd`): il successore, che funziona anche con Python e altri linguaggi e produce pagine web, documenti Word, PDF e presentazioni. Le versioni recenti di RStudio lo includono già.

Per un nuovo lavoro si consiglia Quarto; molti progetti esistenti usano ancora R Markdown, quindi conviene saper leggere entrambi. Le idee sono le stesse: il file ha un'intestazione, del testo scritto in **Markdown** (titoli con `#`, elenchi con `-`) e dei **blocchi di codice** (`chunk`) che R esegue ogni volta.

**Rendere** il report vuol dire trasformare il file in un documento finito. In RStudio c'è il pulsante «Render». Vuoi vedere come si crea il primo documento Quarto? Il video è in inglese, con sottotitoli attivabili:

<Scene title="Anatomia di un file Quarto">
Un documento Quarto minimo:

````markdown
---
title: "Report ordini"
format: html
params:
  citta: "Roma"
---

```{r}
#| echo: false
#| message: false
library(tidyverse)
ordini <- read_csv("dati/ordini.csv")
```

## Totale per `r params$citta`

Gli ordini di `r params$citta` valgono
`r ordini |> filter(citta == params$citta) |> pull(importo) |> sum()` euro.
````

Le tre parti:

1. **L'intestazione (YAML)**, tra le righe `---`: titolo, formato di uscita (`html`, `docx`, `pdf`) e i parametri;
2. **I blocchi di codice**, che cominciano con la riga `{r}` preceduta da tre apici rovesciati. Le righe che iniziano con `#|` sono opzioni: `echo: false` nasconde il codice e mostra solo il risultato, `message: false` nasconde i messaggi dei pacchetti;
3. **Il testo**, in Markdown, con **codice in linea**: `` `r espressione` `` viene sostituito dal risultato. Così il numero nella frase è sempre quello giusto.

In R Markdown le opzioni si scrivono nell'intestazione del blocco, ``{r, echo=FALSE}``, e il formato con `output: html_document`. Il resto è identico.

<Callout kind="trucco">
Per un html che si apre da solo, anche quando lo mandi per email, aggiungi nell'intestazione `format:` poi `html:` poi `embed-resources: true`: grafici e stili finiscono dentro il file.
</Callout>

<Say who="sensei">Tre pezzi: intestazione, codice, testo. Quando un report si rompe, di solito è uno dei tre che non si parla con gli altri.</Say>
</Scene>

<Scene title="Parametri e rendere da un file">
Un **parametro** è un valore che puoi cambiare senza toccare il codice. Nell'esempio il parametro `citta` vale `"Roma"`; nel testo e nel codice si legge con `params$citta`.

Per rendere il report dal terminale, senza aprire RStudio:

```bash
quarto render report.qmd
quarto render report.qmd -P citta:Milano --output report-milano.html
```

La seconda riga rifà **lo stesso report per Milano**, con un altro nome di file. Dentro R si può fare lo stesso con la funzione `quarto_render()` del pacchetto `quarto` e l'argomento `execute_params = list(citta = "Milano")`.

Con R Markdown il comando equivalente è:

```r
rmarkdown::render("report.Rmd", params = list(citta = "Milano"), output_file = "report-milano.html")
```

Un parametro, tre città, tre report: un ciclo che chiama la funzione per `"Roma"`, `"Milano"` e `"Torino"` produce l'intero pacchetto mensile in pochi secondi.

<Callout kind="attenzione">
Ogni rendering parte da una **sessione pulita**: il report non vede le variabili che hai creato in console. Tutto ciò che serve (pacchetti, lettura dei dati) deve essere **dentro** il file. Se un grafico serve di nuovo, va ricostruito nel report.
</Callout>

Se il report usa numeri casuali, aggiungi `set.seed(123)` all'inizio: altrimenti ogni rendering darà un risultato diverso.

<Say who="assistente">Il test è semplice: chiudi tutto, riavvia R, premi Render. Se funziona, il report è riproducibile.</Say>
</Scene>

<Scene title="Cartelle di progetto e versioni">
Un report riproducibile vive in una **cartella di progetto** ordinata, come quella della prima lezione:

```text
vendite/
├── vendite.Rproj
├── report.qmd
├── dati/        file di partenza, mai modificati a mano
├── script/      funzioni e pulizie riusabili
└── output/      grafici e report prodotti
```

Regole:

- **percorsi relativi**: `"dati/ordini.csv"`; il pacchetto `here` con `here::here("dati", "ordini.csv")` funziona anche quando il file sta in una sottocartella;
- **pacchetti con versione**: il pacchetto `renv` registra le versioni usate (`renv::init()`, poi `renv::snapshot()`) e permette a un collega di ricrearle con `renv::restore()`;
- **versionare con Git**: salvi il codice a ogni tappa e puoi tornare indietro. Si versionano script e `.qmd`; si aggiungono a `.gitignore` le cartelle temporanee di RStudio (`.Rproj.user/`, `.Rhistory`, `.RData`).

<Callout kind="attenzione">
I dati con informazioni su persone (nomi, indirizzi, dati di salute) **non vanno in un repository condiviso**. Il GDPR chiede di limitare i dati personali al minimo necessario. Il codice si condivide, i dati sensibili restano dove sono protetti, e per gli esempi si usano dati finti o anonimizzati.
</Callout>

<Say who="sensei">Un lavoro riproducibile è un lavoro onesto: chiunque può rifarlo e controllare. È il miglior biglietto da visita di un analista.</Say>

<Scene title="Rapporto finale">
<Recap xp={20}>
- Un report riproducibile (Quarto `.qmd` o R Markdown `.Rmd`) unisce intestazione YAML, testo Markdown e blocchi di codice: i numeri nel testo li scrive il codice.
- I parametri permettono di rifare lo stesso report con valori diversi, con `quarto render report.qmd -P citta:Milano` oppure `rmarkdown::render(..., params = ...)`.
- Cartella di progetto ordinata, percorsi relativi, `renv` per le versioni, Git per la storia del codice; i dati personali non si versionano.
</Recap>
