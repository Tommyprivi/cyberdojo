<Scene title="Il CSV e read_csv">
Un file **CSV** (in inglese comma-separated values, valori separati da virgola) è un semplice file di testo: una riga per ogni riga della tabella, i campi separati da un carattere. La prima riga contiene i nomi delle colonne.

In questa lezione i dati stanno dentro il testo, così gli esempi funzionano ovunque: `StringIO` crea un «finto file» in memoria. Nel lavoro vero al posto di `StringIO(testo)` scrivi il nome del file.

```python
import pandas as pd
from io import StringIO

testo = """cliente,citta,importo
Anna,Roma,40.5
Bruno,Milano,20
Carla,Roma,40
"""
ordini = pd.read_csv(StringIO(testo))
print(ordini)
print(ordini.dtypes)
```

```text
  cliente   citta  importo
0    Anna    Roma     40.5
1   Bruno  Milano     20.0
2   Carla    Roma     40.0
cliente     object
citta       object
importo    float64
dtype: object
```

Nota `importo`: i valori 40.5, 20 e 40 diventano tutti `float64`, perché basta un decimale per far diventare la colonna intera «con la virgola».

<Scene title="Dov'è il file? I percorsi">
`pd.read_csv("ordini.csv")` cerca il file **nella cartella di lavoro** del notebook. Se non lo trova:

```text
FileNotFoundError: [Errno 2] No such file or directory: 'ordini.csv'
```

Significa quasi sempre che il file è da un'altra parte. Due strade:

- **percorso relativo**: parte dalla cartella di lavoro, per esempio `"dati/ordini.csv"` (cartella `dati`, file dentro);
- **percorso assoluto**: parte dalla radice del disco, per esempio `"/home/giulia/dati/ordini.csv"` su Linux o macOS e `"C:/Users/giulia/dati/ordini.csv"` su Windows.

Su Windows usa le barre normali `/` nei percorsi, oppure metti una `r` davanti alle virgolette: `r"C:\Users\giulia\ordini.csv"`. La barra rovesciata da sola, in Python, ha un significato speciale.

In **Google Colab** il file va prima caricato: si apre l'icona della cartella a sinistra e si trascina il file. Poi basta il nome. `read_csv` accetta anche un indirizzo web, `pd.read_csv("https://...")`, se il file è pubblico.

Non sai dove sei? Scrivi `import os` e poi `print(os.getcwd())`: ti dice qual è la cartella di lavoro. `os.listdir()` elenca i file che contiene.
</Callout>

<Scene title="Separatori e virgole decimali">
Excel in italiano esporta i CSV con il **punto e virgola** come separatore, perché la virgola gli serve per i decimali. Se non lo dici, pandas non lo indovina.

```python
testo = "cliente;quantita\nAnna;3\nBruno;2\n"
print(pd.read_csv(StringIO(testo)))
print(pd.read_csv(StringIO(testo), sep=";"))
```

```text
   cliente;quantita
0            Anna;3
1           Bruno;2
   cliente  quantita
0     Anna         3
1    Bruno         2
```

La prima lettura è il sintomo tipico: **una sola colonna** con il nome tutto attaccato. Il rimedio è `sep=";"`.

Se i numeri hanno la virgola decimale, serve anche `decimal=","`:

```python
testo = "cliente;importo\nAnna;40,5\nBruno;20,0\n"
a = pd.read_csv(StringIO(testo), sep=";")
b = pd.read_csv(StringIO(testo), sep=";", decimal=",")
print(a.dtypes)
print(b.dtypes)
print(b)
```

```text
cliente    object
importo    object
dtype: object
cliente     object
importo    float64
dtype: object
   cliente  importo
0     Anna     40.5
1    Bruno     20.0
```

Senza `decimal=","` «40,5» resta un **testo**: la colonna è `object` e non puoi farci la media.

<Scene title="Le lettere strane: la codifica">
Un file di testo salva ogni lettera come numero secondo una **codifica**. Oggi la più usata è **UTF-8**, che pandas si aspetta. I file esportati da vecchi programmi Windows possono usare altre codifiche, come **latin-1** (detta anche cp1252), dove una lettera come «ì» ha un numero diverso.

```python
from io import BytesIO

dati = "citta\nPerugia\nForlì\n".encode("latin-1")
print(pd.read_csv(BytesIO(dati), encoding="latin-1"))
```

```text
     citta
0  Perugia
1    Forlì
```

Con la codifica sbagliata puoi ricevere due sintomi:

- un errore che comincia con `UnicodeDecodeError: 'utf-8' codec can't decode byte`: il file non è UTF-8, prova `encoding="latin-1"`;
- nessun errore, ma lettere sbagliate: al posto di «ì» compare «Ã¬» (accade quando un file UTF-8 viene letto come latin-1).

<Callout kind="regola">
I nomi con gli accenti sono il primo posto dove guardare. Dopo ogni lettura controlla `head()`: se «Forlì» è diventato «ForlÃ¬», la codifica è sbagliata.
</Callout>

<Say who="sensei">Sembra un dettaglio da programmatori. Poi scopri che Perugia e Forlì non sono finite nel report. Guarda sempre le prime righe.</Say>

<Scene title="Il tipo delle colonne">
pandas prova a indovinare il tipo di ogni colonna, ma non sempre ci azzecca. Due casi classici.

**Codici che sembrano numeri.** Un CAP come `00100` letto come numero perde gli zeri iniziali. Si chiede di leggerlo come testo con `dtype`:

```python
testo = "citta,cap,abitanti\nRoma,00100,2800000\nMilano,20100,1400000\n"
print(pd.read_csv(StringIO(testo)))
print(pd.read_csv(StringIO(testo), dtype={"cap": str}))
```

```text
    citta    cap  abitanti
0    Roma    100   2800000
1  Milano  20100   1400000
    citta    cap  abitanti
0    Roma  00100   2800000
1  Milano  20100   1400000
```

**Numeri con una scritta in mezzo.** Se una cella contiene `n.d.` («non disponibile»), tutta la colonna diventa testo. Con `na_values` dici quali scritte significano «manca»:

```python
testo = "citta,importo\nRoma,40\nMilano,n.d.\n"
print(pd.read_csv(StringIO(testo)).dtypes)
print(pd.read_csv(StringIO(testo), na_values=["n.d."]))
```

```text
citta      object
importo    object
dtype: object
    citta  importo
0    Roma     40.0
1  Milano      NaN
```

`NaN` è il valore mancante di pandas: significa «non so quanto vale» e non viene contato nelle medie.

<Recap xp={20}>
- `pd.read_csv("file.csv")` cerca il file nella cartella di lavoro: se non lo trova, FileNotFoundError. Usa un percorso relativo o assoluto.
