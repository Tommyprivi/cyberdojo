<Scene title="Il lago">
Un **data lake** («lago di dati») è un grande spazio di archiviazione dove si **versano i file così come arrivano**: tabelle, testi, immagini. Costa poco e non chiede di decidere la forma in anticipo.

Il confronto con il warehouse:

| | Warehouse | Lake |
|---|-----------|------|
| Cosa contiene | Tabelle ordinate | File di ogni tipo |
| Forma dei dati | Decisa **prima** di caricare | Decisa **quando si legge** |
| Costo di archiviazione | Più alto | Più basso |
| Rischio | Rigido | Disordine |

<Callout kind="attenzione">
Un lago senza cartelle ordinate, nomi chiari e descrizioni diventa una **palude** (data swamp): i dati ci sono ma nessuno sa trovarli o fidarsene.
</Callout>

<Say who="assistente">Il warehouse è una libreria con le etichette. Il lake è un magazzino con scatoloni: serve comunque un registro.</Say>
</Scene>

{/* screen */}

<Scene title="Tre formati di file">
Nel lake si incontrano soprattutto tre formati. Lo stesso dato in due di essi:

<Log lines={[
  "CSV (testo, una riga per record):",
  "id,citta,totale",
  "1,Roma,20",
  "2,Milano,35",
  "",
  "JSON (testo, con nomi dei campi):",
  "[",
  "  {\"id\": 1, \"citta\": \"Roma\", \"totale\": 20},",
  "  {\"id\": 2, \"citta\": \"Milano\", \"totale\": 35}",
  "]",
]} />

- **CSV**: semplice, lo apre chiunque, ma non dice i tipi dei dati.
- **JSON**: ogni record porta con sé i nomi dei campi; adatto a dati annidati, come quelli delle API.
- **Parquet**: formato **binario** (non si legge a occhio) che tiene i dati **per colonna**, li comprime e conserva i tipi. Per analizzare una colonna sola, legge solo quella.

<Callout kind="trucco">
Per scambiarsi pochi dati: CSV o JSON. Per grandi quantità da analizzare spesso: **Parquet**.
</Callout>

<Scene title="Il lakehouse">
Il lake è economico ma disordinato; il warehouse è affidabile ma rigido. Il **lakehouse** prova a prendere il meglio di entrambi.

I dati restano come **file nel lake** (di solito Parquet), ma sopra c'è uno **strato di gestione** che tiene un registro delle tabelle: quali file ne fanno parte, che forma hanno, quali modifiche sono state fatte. Strumenti come Delta Lake e Apache Iceberg fanno questo lavoro.

Risultato: si può fare SQL come in un warehouse, sui file economici del lake, con più garanzie (per esempio modifiche che riescono per intero o non riescono affatto).

<Callout kind="curiosita">
Il lakehouse non è magia: è un lake con un **registro** ben tenuto.
</Callout>

<Say who="assistente">Lake per conservare, warehouse per rispondere, lakehouse per volerli un po' insieme.</Say>
</Scene>

<Scene title="Rapporto finale">
<Recap xp={20}>
- Il data lake conserva file di ogni tipo a basso costo; la forma si decide quando si leggono.
- CSV e JSON sono testo semplice; Parquet è binario, per colonne e compresso: ideale per analisi.
- Il lakehouse aggiunge al lake un registro delle tabelle, per usare SQL con più garanzie.
</Recap>
