<Scene title="Cosa fa sudo">
**sudo** significa «super user do»: esegui **questo singolo comando** con i poteri dell'amministratore (root), poi torna normale.

<Log lines={[
  "studente@lab:~$ cat /var/log/auth.log",
  "cat: /var/log/auth.log: Permission denied",
  "studente@lab:~$ sudo cat /var/log/auth.log",
  "[sudo] password for studente:",
]} caption="Senza sudo il file è negato. Con sudo, il sistema chiede la password." />

Attenzione: sudo chiede **la tua password**, non quella di root. Serve per verificare che sia davvero tu davanti alla tastiera, e che tu sia tra gli utenti autorizzati (il file `/etc/sudoers` decide chi).

<Callout kind="curiosita">
Ogni uso di sudo viene **registrato** nei log. È una delle differenze rispetto a «essere root»: con sudo resta traccia di chi ha fatto cosa.
</Callout>

<Say who="assistente">Sudo è un prestito. Il potere resta a root: tu lo prendi per un comando e lo restituisci.</Say>
</Scene>

{/* screen */}

<Scene title="Il privilegio minimo">
Il principio dietro tutto è uno solo: **privilegio minimo**. Ogni utente e ogni programma deve avere **solo** i permessi che gli servono per fare il proprio lavoro. Non uno di più.

<Callout kind="regola">
Privilegio minimo: se per leggere un file basta il permesso di lettura, non dare la scrittura. Se basta un comando con sudo, non aprire una shell da root.
</Callout>

Pensa a un hotel: la receptionist ha la chiave della reception, non la chiave di tutte le camere. Se qualcuno le ruba la chiave, il danno resta piccolo.

<Say who="sensei">Un privilegio che non serve è un rischio gratis. Non regalarlo.</Say>
</Scene>

{/* screen */}

<Scene title="Quando serve davvero">
Cose che di solito richiedono sudo: installare o rimuovere programmi, cambiare la configurazione del sistema, leggere file riservati, fermare servizi.

Cose che **non** richiedono sudo: guardare le tue cartelle, scrivere i tuoi file, usare i tuoi programmi.

<Guided
  steps={[
    "Un comando dà «Permission denied». Prima domanda: è un file mio o del sistema?",
    "Se è mio, forse devo solo sistemare i permessi con chmod: niente sudo.",
    "Se è del sistema e ne ho davvero bisogno, uso sudo per quel solo comando.",
    "Dopo, controllo cosa è cambiato. Non resto in una shell da root «già che ci sono».",
  ]}
/>

<Callout kind="attenzione">
Il simbolo `#` sul prompt invece di `$` di solito significa che sei root. Se lo vedi, rallenta: ogni comando ha il massimo del peso.
</Callout>

<Say who="assistente">Quando c'è dubbio, prima chiediti perché il comando è negato. Il sudo viene dopo.</Say>
</Scene>

{/* screen */}

<Scene title="I rischi">
Torniamo alla domanda di Luca: «Lo incollo?»

Un comando con sudo gira con **tutti i poteri**. Se contiene qualcosa di ostile (scarica un programma da un sito sconosciuto, cancella file, apre un accesso da fuori) lo fa senza fermarsi, perché tu hai detto «sì, puoi».
