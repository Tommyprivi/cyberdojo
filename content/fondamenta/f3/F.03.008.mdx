<Scene title="Cosa è successo stanotte?">
Stamattina Marta controlla il server dei dati. Tutto funziona, ma qualcuno nota che la porta 22 è stata molto «viva» durante la notte.

Un computer non ti racconta da solo ciò che è successo, ma tiene **un diario**. Ogni accesso, ogni errore, ogni sudo: Linux scrive tutto. La domanda del caso: **dove sta quel diario, e come si legge?**

<Say who="sensei">Un analista non indovina. Apre il registro e legge. Cominciamo dal posto giusto.</Say>
</Scene>

{/* screen */}

<Scene title="La cartella /var/log">
I registri, in inglese **log**, stanno quasi tutti nella cartella `/var/log`.

<Log lines={[
  "studente@lab:~$ ls /var/log",
  "alternatives.log  apt  auth.log  boot.log  dpkg.log  journal  syslog",
]} caption="Elenco semplificato. Ogni file ha un tema." />

I più utili per cominciare:

- `auth.log`: accessi, tentativi falliti, uso di sudo
- `syslog`: messaggi generali del sistema
- `apt/`: cosa è stato installato o aggiornato

<Callout kind="curiosita">
Molti file di log sono leggibili solo da root: servono `sudo`, e per il principio del privilegio minimo si usa solo per quel comando di lettura.
</Callout>

<Callout kind="attenzione">
Su alcune installazioni recenti il file `auth.log` non esiste: gli stessi eventi sono solo nel giornale di systemd (lo vedi più avanti con `journalctl`).
</Callout>

<Say who="assistente">auth.log è il file da cui parte quasi ogni indagine sugli accessi. Memorizza il nome.</Say>
</Scene>

<Scene title="Leggere senza annegare">
Un log può avere **migliaia** di righe. Non si apre tutto con `cat`: si guardano le **prime** o le **ultime**.

- `head -n 10 file`: le prime 10 righe
- `tail -n 10 file`: le ultime 10
- `tail -f file`: segue il file **in diretta**, mostrando le righe nuove appena arrivano (si esce con Ctrl+C)

<Log lines={[
  "studente@lab:~$ sudo tail -n 4 /var/log/auth.log",
  "Oct 12 02:11:07 server sshd[2310]: Failed password for ale from 203.0.113.9 port 51022 ssh2",
  "Oct 12 02:11:09 server sshd[2312]: Failed password for ale from 203.0.113.9 port 51024 ssh2",
  "Oct 12 02:11:12 server sshd[2315]: Failed password for ale from 203.0.113.9 port 51027 ssh2",
  "Oct 12 02:14:30 server sshd[2399]: Accepted password for marta from 192.168.1.20 port 40112 ssh2",
]} caption="Le ultime righe di auth.log. L'indirizzo 203.0.113.9 è riservato alla documentazione, quindi non è un computer vero." />

<Say who="sensei">Le ultime righe dicono cosa è successo di recente. Le prime, com'era cominciata la giornata. Scegli in base alla domanda.</Say>
</Scene>

<Callout kind="attenzione">
Un solo `Failed password` non è un attacco: capita a tutti di sbagliare. Un attacco si riconosce dal **ripetersi**: molti tentativi, in poco tempo, dallo stesso indirizzo.
</Callout>

<Say who="assistente">Tre cose sempre: quando, chi, da dove. Con quelle tre ricostruisci quasi tutta la storia.</Say>

<Scene title="journalctl">
Molte distribuzioni moderne raccolgono i log anche in un **giornale** gestito da systemd. Si legge con `journalctl`.

<Log lines={[
  "studente@lab:~$ sudo journalctl -u ssh -n 3",
  "Oct 12 02:11:12 server sshd[2315]: Failed password for ale from 203.0.113.9",
  "Oct 12 02:14:30 server sshd[2399]: Accepted password for marta from 192.168.1.20",
  "Oct 12 02:14:30 server systemd[1]: Started session 41 of user marta.",
]} caption="-u ssh mostra solo i messaggi del servizio ssh; -n 3 limita a tre righe." />

<Video />

<Scene title="Il collegamento con la cybersecurity">
Chi difende un sistema vive di log. Nel corso **Cybersecurity** ritroverai tutto questo: rilevare accessi sospetti, ricostruire un incidente, capire cosa ha fatto un attaccante.

<Callout kind="regola">
I log servono a **ricostruire** cosa è successo e quando. Per questo un attaccante cerca di cancellarli: se spariscono, sparisce la storia. Anche per questo i log importanti si copiano su un altro computer.
</Callout>

<Scene title="Rapporto finale">
<Recap xp={20}>
- Caso chiuso: il diario della notte sta in /var/log e nel giornale di systemd; in auth.log si vedono tentativi ripetuti sull'utente ale dalla porta 22.
- I log stanno in /var/log (auth.log per gli accessi, syslog per il sistema) e nel giornale di systemd (journalctl).
- Si leggono a pezzi: head per le prime righe, tail per le ultime, tail -f per seguirli in diretta.
- Una riga dice quando, chi e da dove. Un attacco si riconosce dal ripetersi, non da un singolo errore.
</Recap>
