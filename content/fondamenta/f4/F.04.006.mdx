<Scene title="Uno script per tutti i log">
Lo script della scorsa lezione funziona solo con `accessi.log`. Ma al SOC i log sono tanti: uno per ogni server. Vuoi **un solo script** a cui dire quale file guardare.

Inoltre vuoi che si comporti bene quando qualcosa va storto: file mancante, nome sbagliato, comando che fallisce. Uno script che continua come se niente fosse può combinare guai.

<Scene title="Argomenti e codici di uscita">
Quello che scrivi dopo il nome dello script sono gli **argomenti**. Dentro lo script: **`$1`** è il primo, **`$2`** il secondo, **`$#`** dice **quanti** sono, **`$0`** è il nome dello script.

Ogni comando, quando finisce, lascia un **codice di uscita**: **0 = tutto bene**, **qualsiasi altro numero = errore**. Si legge con **`$?`**. Lo script lo restituisce con **`exit N`**.

<Log lines={[
  "studente@lab:~$ grep -q FALLITO accessi.log; echo $?",
  "0",
  "studente@lab:~$ grep -q ZZZ accessi.log; echo $?",
  "1",
  "studente@lab:~$ grep -q FALLITO accessi.log && echo \"trovato\"",
  "trovato",
]} caption="-q = silenzioso. Con && il secondo comando parte solo se il primo ha avuto successo (codice 0)." />

<Callout kind="attenzione">
Qui lo zero vuol dire **successo**, non «falso». Un comando che finisce con 0 è andato bene; 1, 2, 127... sono errori diversi.
</Callout>

<Say who="assistente">Il codice di uscita è la risposta in una parola del comando: «tutto bene» oppure «qualcosa è andato storto, e questo è il numero».</Say>
</Scene>

{/* screen */}

<Scene title="Cicli for e while">
Il ciclo **`for`** ripete dei comandi per **ogni elemento** di un elenco. Il ciclo **`while`** ripete **finché una condizione è vera**.

<Log lines={[
  "studente@lab:~$ for p in FALLITO OK web; do echo \"Cerco $p\"; done",
  "Cerco FALLITO",
  "Cerco OK",
  "Cerco web",
  "studente@lab:~$ n=1; while [ \"$n\" -le 3 ]; do echo \"Giro $n\"; n=$((n + 1)); done",
  "Giro 1",
  "Giro 2",
  "Giro 3",
  "studente@lab:~$ while read -r ora ip resto; do echo \"$ora -> $ip\"; done < accessi.log | head -n 2",
  "03:01 -> 203.0.113.9",
  "03:02 -> 203.0.113.9",
]} caption="Il terzo while legge il file riga per riga, spezzando in campi." />

Dentro `$(( ))` bash fa i **calcoli**: `n=$((n + 1))` aumenta n di uno. Se la condizione del `while` non diventa mai falsa, il ciclo non finisce mai: **Ctrl+C** lo interrompe.

<Say who="sensei">for quando sai cosa ripetere. while quando sai quando fermarti. E ricorda sempre di far avanzare il contatore.</Say>
</Scene>

{/* screen */}

<Scene title="Funzioni">
Una **funzione** è un blocco di comandi con un nome. La definisci una volta, la richiami quante volte vuoi. Gli argomenti della funzione sono, di nuovo, `$1`, `$2`...

<Log lines={[
  "studente@lab:~$ saluta() { echo \"Ciao $1\"; }",
  "studente@lab:~$ saluta Mario",
  "Ciao Mario",
  "studente@lab:~$ saluta Lucia",
  "Ciao Lucia",
]} caption="Una funzione con un solo argomento." />

<Callout kind="trucco">
Una funzione serve quando ripeti lo stesso gruppo di comandi: la scrivi una volta sola, e se devi correggerla lo fai in un posto solo.
</Callout>

<Say who="assistente">Come una ricetta con un nome: «saluta», «conta». Da quel momento basta chiamarla.</Say>
</Scene>

<Scene title="Script prudenti">
Ecco lo script completo, `analizza.sh`, con le difese in cima:

<Log lines={[
  "studente@lab:~$ cat analizza.sh",
  "#!/bin/bash",
  "set -euo pipefail",
  "",
  "if [ $# -lt 1 ]; then",
  "  echo \"Uso: $0 file-di-log\" >&2",
  "  exit 1",
  "fi",
  "",
  "LOG=\"$1\"",
  "if [ ! -f \"$LOG\" ]; then",
  "  echo \"File non trovato: $LOG\" >&2",
  "  exit 2",
  "fi",
  "",
  "conta() {",
  "  grep -c \"$1\" \"$LOG\" || true",
  "}",
  "",
  "for parola in FALLITO OK; do",
  "  echo \"$parola: $(conta \"$parola\")\"",
  "done",
]} caption="Gli errori vanno su stderr (>&2) con un codice di uscita diverso da 0." />

<Log lines={[
  "studente@lab:~$ ./analizza.sh accessi.log",
  "FALLITO: 4",
  "OK: 4",
  "studente@lab:~$ ./analizza.sh",
  "Uso: ./analizza.sh file-di-log",
  "studente@lab:~$ echo $?",
  "1",
  "studente@lab:~$ ./analizza.sh manca.log",
  "File non trovato: manca.log",
  "studente@lab:~$ echo $?",
  "2",
]} caption="Ogni errore ha il suo codice: 1 mancano gli argomenti, 2 file inesistente." />

<Say who="sensei">Prima i controlli, poi il lavoro. Se i dati sono sbagliati, lo script si ferma e lo dice. Meglio un errore chiaro che un risultato falso.</Say>
</Scene>

<Scene title="Le tre difese e tocca a te">
La riga `set -euo pipefail` attiva tre protezioni:

<Guided
  steps={[
    "-e: lo script si ferma al primo comando che fallisce. Senza, un cd sbagliato non ferma niente: i comandi dopo lavorano nella cartella sbagliata.",
    "-u: usare una variabile che non esiste è un errore. Senza, un nome scritto male diventa una stringa vuota in silenzio.",
    "-o pipefail: in una pipeline, se un comando in mezzo fallisce, l'errore non si perde.",
    "|| true dopo un comando dice «un fallimento qui è normale»: serve con grep -c, che esce con 1 se non trova niente.",
  ]}
/>

<Callout kind="attenzione">
**Le virgolette (quoting) sono la quarta difesa.** Se `f` contiene «mio file.txt», `ls $f` lo spezza in due argomenti. Con `ls "$f"` resta uno solo.
</Callout>

<Scene title="Rapporto finale">
<Recap xp={20}>
- `$1`, `$2` sono gli argomenti, `$#` quanti sono; `for` ripete per ogni elemento, `while` finché la condizione è vera; le funzioni raggruppano comandi.
- Codice di uscita: 0 = successo, altro = errore; si legge con `$?` e si restituisce con `exit N`.
- Script prudenti: `set -euo pipefail`, controlli iniziali, errori su stderr (`>&2`) e sempre virgolette attorno alle variabili.
</Recap>
