<Scene title="Scrivere e leggere con with open">
`open(nome, modo)` apre un file. I modi principali sono `"r"` (leggere, il predefinito), `"w"` (scrivere, **cancella** il contenuto precedente) e `"a"` (aggiungere in fondo). Si usa quasi sempre con `with`, che **chiude il file da solo** alla fine del blocco, anche se c'è un errore.

Prima creiamo il file di prova:

```python
with open("accessi.log", "w", encoding="utf-8") as f:
    f.write("03:10 OK ada 10.0.0.5\n")
    f.write("03:11 FAILED root 203.0.113.9\n")
    f.write("03:12 FAILED admin 203.0.113.9\n")
    f.write("03:13 OK bruno 10.0.0.7\n")
```

Il `\n` è il carattere di **a capo**: `write()` non lo aggiunge da solo. Ora leggiamo, una riga alla volta:

```python
with open("accessi.log", encoding="utf-8") as f:
    for riga in f:
        print(riga.strip())
```

Output:

```text
03:10 OK ada 10.0.0.5
03:11 FAILED root 203.0.113.9
03:12 FAILED admin 203.0.113.9
03:13 OK bruno 10.0.0.7
```

<Callout kind="attenzione">
Ogni riga letta finisce con `\n`. Se non usi `strip()`, `print` aggiunge un altro a capo e vedi righe vuote in mezzo. Con `f.read()` leggi invece **tutto il file in un solo testo**.
</Callout>

<Scene title="Filtrare un log">
Ecco il compito di Marta: leggere `accessi.log`, tenere le righe con `FAILED` e salvarle in `falliti.txt`.

```python
falliti = []
with open("accessi.log", encoding="utf-8") as f:
    for riga in f:
        if "FAILED" in riga:
            falliti.append(riga.strip())

with open("falliti.txt", "w", encoding="utf-8") as out:
    for riga in falliti:
        out.write(riga + "\n")
print(len(falliti), "righe salvate")
```

Output:

```text
2 righe salvate
```

In `falliti.txt` ci sono le due righe di `root` e `admin`. Rileggi il programma: è la lezione sui cicli, sulle decisioni e sulle liste, tutte insieme, più un file in entrata e uno in uscita.

<Callout kind="trucco">
Due blocchi `with` separati: prima si legge e si chiude, poi si scrive. Così non rischi di leggere e scrivere sullo stesso file nello stesso momento.
</Callout>

<Scene title="Se il file non c'è: try e except">
Se il file non esiste, `open()` si ferma con un errore: `FileNotFoundError`. Con `try` e `except` lo gestisci tu, senza far crollare lo script.

```python
try:
    with open("manca.log", encoding="utf-8") as f:
        print(f.read())
except FileNotFoundError:
    print("File non trovato: controlla il percorso")
```

Output (supponendo che `manca.log` non esista):

```text
File non trovato: controlla il percorso
```

Python esegue il blocco `try`. Se compare l'errore **nominato** dopo `except`, salta lì; altrimenti il blocco `except` viene ignorato.

<Callout kind="attenzione">
Nomina sempre l'errore che ti aspetti (`FileNotFoundError`, `ValueError`, `ZeroDivisionError`). Un `except` generico nasconde anche gli errori che non conosci, e poi non capisci più cosa è successo.
</Callout>

<Scene title="I file CSV">
Un file **CSV** è una tabella scritta come testo, con i valori separati da virgole: la prima riga è l'intestazione. Python ha il modulo `csv` per leggerli e scriverli senza spaccare le righe a mano.

```python
import csv

with open("host.csv", "w", newline="", encoding="utf-8") as f:
    scrittore = csv.writer(f)
    scrittore.writerow(["nome", "ip", "porta"])
    scrittore.writerow(["web1", "10.0.0.5", 80])
    scrittore.writerow(["db1", "10.0.0.9", 5432])

with open("host.csv", newline="", encoding="utf-8") as f:
    for riga in csv.DictReader(f):
        print(riga["nome"], riga["porta"])
```

Output:

```text
web1 80
db1 5432
```

`DictReader` ti dà ogni riga come un **dizionario**, con le intestazioni come chiavi: lo hai studiato la volta scorsa.

<Callout kind="attenzione">
I valori letti da un CSV sono **sempre testo**: `riga["porta"]` è `"80"`, non `80`. Per fare i conti serve `int(riga["porta"])`.
</Callout>

<Scene title="Moduli: import, pathlib, json">
Python ha già pronti tanti **moduli**: file di funzioni scritte da altri. Si caricano con `import`. Tre da conoscere subito:

- `pathlib` per lavorare con file e cartelle (esiste? come si chiama? che estensione ha?)
- `json` per salvare e leggere dati strutturati, molto usati nelle configurazioni e nelle API
- `os` per funzioni del sistema operativo, per esempio `os.getcwd()` mostra la cartella corrente

```python
import json
from pathlib import Path

config = {"soglia": 5, "porte": [22, 80]}
Path("config.json").write_text(json.dumps(config), encoding="utf-8")
letto = json.loads(Path("config.json").read_text(encoding="utf-8"))
print(letto["soglia"])
print(Path("config.json").exists())
print(Path("config.json").suffix)
```

Output:

```text
5
True
.json
```

Due modi di importare: `import json` e poi `json.loads(...)`, oppure `from pathlib import Path` e poi solo `Path(...)`.

<Callout kind="curiosita">
`json.dumps` trasforma un dizionario in **testo** JSON; `json.loads` fa il contrario. La `s` finale sta per «string».
</Callout>
