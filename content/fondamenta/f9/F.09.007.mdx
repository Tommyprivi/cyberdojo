<Scene title="def: definire e chiamare">
Si definisce con `def`, il nome, le parentesi e i due punti. Il corpo è rientrato. I valori che la funzione riceve si chiamano **parametri**.

```python
def classifica(porta):
    if porta == 22:
        return "remoto"
    elif porta in [80, 443]:
        return "web"
    return "altro"

print(classifica(443))
print(classifica(3389))
```

Output:

```text
web
altro
```

`classifica(443)` è la **chiamata**: il valore 443 finisce nel parametro `porta`. La funzione parte solo quando la chiami; la sola definizione non stampa niente.

Un parametro può avere un **valore predefinito**: se chi chiama non lo dà, si usa quello.

```python
def avvisa(messaggio, livello="info"):
    return f"[{livello}] {messaggio}"

print(avvisa("disco quasi pieno"))
print(avvisa("login fallito", "alto"))
```

Output:

```text
[info] disco quasi pieno
[alto] login fallito
```

<Scene title="return o print?">
Sono due cose diverse. `print()` **mostra** un valore a chi guarda lo schermo. `return` **restituisce** un valore a chi ha chiamato la funzione, che può usarlo per altri calcoli.

```python
def somma(a, b):
    print(a + b)

x = somma(2, 3)
print(x)
```

Output:

```text
5
None
```

La funzione ha stampato 5, ma non ha restituito niente: `x` contiene `None`, il valore speciale che significa «nulla». Una funzione senza `return` restituisce sempre `None`.

<Callout kind="regola">
Quando la funzione deve **calcolare** qualcosa, usa `return`. Lascia il `print()` a chi chiama: così puoi riusare il risultato dove ti serve.
</Callout>

Dopo un `return` la funzione **finisce subito**: le righe sotto non vengono eseguite.

<Say who="sensei">Print è per gli occhi. Return è per il programma. Se ti serve il valore dopo, è return.</Say>
</Scene>

<Scene title="L'ambito delle variabili">
Una variabile creata dentro una funzione vive **solo lì dentro**. Fuori non esiste.

```python
def conta():
    totale = 10
    return totale

conta()
print(totale)
```

Python risponde:

```text
NameError: name 'totale' is not defined
```

Il contrario funziona: una funzione può **leggere** una variabile creata fuori.

```python
limite = 5

def sopra_limite(n):
    return n > limite

print(sopra_limite(7))
```

Output:

```text
True
```

<Callout kind="trucco">
Buona abitudine: i dati entrano dai **parametri** ed escono dal **return**. Una funzione che non dipende da variabili esterne si capisce e si prova più facilmente.
</Callout>

<Say who="assistente">Pensa a una stanza chiusa: dentro puoi guardare fuori dalla finestra, ma ciò che costruisci dentro resta lì.</Say>
</Scene>

<Scene title="Piccole e testabili">
Una buona funzione fa **una cosa sola** ed è abbastanza piccola da stare in poche righe. Il vantaggio è che la puoi **provare da sola**, con la parola `assert`: se la condizione è falsa Python si ferma con `AssertionError`, se è vera non succede niente.

```python
def e_porta_valida(n):
    return 1 <= n <= 65535

assert e_porta_valida(22)
assert not e_porta_valida(70000)
print("test ok")
```

Output:

```text
test ok
```

Una porta valida va da 1 a 65535, e il confronto `1 <= n <= 65535` si legge come in matematica. Se domani cambi la funzione e sbagli, gli `assert` ti avvisano subito.

<Callout kind="curiosita">
Nei progetti seri le prove si scrivono **prima** o insieme alla funzione. Non serve un programma speciale per cominciare: bastano due o tre `assert`.
</Callout>

<Scene title="Rapporto finale">
<Recap xp={20}>
- `def nome(parametri):` definisce la funzione, che parte solo quando la chiami; i parametri possono avere un valore predefinito.
- `return` restituisce un valore e chiude la funzione; senza `return` si ottiene `None`.
- Le variabili create dentro una funzione non esistono fuori; funzioni piccole si provano con `assert`.
</Recap>
